# Проект 3. Incident Radar

CLI-утилита для анализа NGINX-логов. Читает логи (файлы, glob-маски или URL),
разбирает строки, фильтрует по датам и строит отчёт со статистикой.

## Состояние проекта в MR3

Реализованы MR1-MR3. Программа считает количество запросов, распределение
кодов ответа, топ-10 ресурсов, средний и максимальный размер ответа и p95.
Отчёты формируются в JSON, Markdown и AsciiDoc.

**Реализованные бонусы**

- **AsciiDoc.** Отчёт в формате `.adoc` содержит статистику и результаты сравнения периодов.
- **Распределение по дням недели.** В отчёте присутствуют все семь дней, включая дни без запросов.
- **Сравнение двух периодов.** Источники читаются за один проход. Для числа запросов, среднего и максимального размера ответа и p95 рассчитываются разница и процентное изменение.
- **Названия HTTP-кодов.** В Markdown и AsciiDoc выводятся подписи, например `200 OK`.
- **Вывод в stdout.** Без `--output-path` отчёт выбранного формата выводится в стандартный поток вывода.
- **Уникальные протоколы.** Отчёт содержит список протоколов без повторов.

## Быстрый старт

Нужен **JDK 25 или новее**. Переменная `JAVA_HOME` должна указывать на JDK.
Gradle устанавливать отдельно не требуется: проект содержит Gradle Wrapper.

Все команды выполняются из корня проекта.

### Windows PowerShell

Один файл:

```powershell
.\gradlew.bat -q run --args="--path=samples/logs/access-2025-03-01.log"
```

Несколько файлов по маске:

```powershell
.\gradlew.bat -q run --args="--path='samples/logs/access-*.log'"
```

Удалённый тестовый лог NGINX из репозитория Elastic Beats:

```powershell
.\gradlew.bat -q run --args="--path=https://raw.githubusercontent.com/elastic/beats/main/filebeat/module/nginx/access/test/access.log"
```

Часть строк в этом тестовом файле отличается от поддерживаемого формата.
Для них ожидаются предупреждения `skipped malformed log line`.

Справка:

```powershell
.\gradlew.bat -q run --args="--help"
```

Каждый основной локальный сэмпл содержит 1500 запросов. Маска
`access-*.log` выбирает два источника с 3000 запросами в сумме.
Ключ `-q` убирает служебный вывод Gradle из `stdout`.

### Linux / macOS

```bash
./gradlew -q run --args="--path='samples/logs/access-*.log'"
./gradlew -q run --args="--help"
```

### Особенность glob-масок в Windows

CLI поддерживает обе формы: `--path VALUE` и `--path=VALUE`.
В Windows Java Launcher может раскрыть glob-маску до передачи аргументов в `main`.
Поэтому рекомендуется `--path='samples/logs/access-*.log'`, как в командах выше: тогда маску раскрывает приложение.

Альтернативно в Windows можно использовать:

```powershell
.\gradlew.bat --% -q run --args="--path '\"./samples/logs/access-*.log\"'"
```


## Параметры CLI

| Параметр | Назначение |
|---|---|
| `--path`, `-p` | Обязательный источник: локальный файл, glob-маска или HTTP/HTTPS URL |
| `--output-format`, `-f` | Формат отчёта: `json` (`.json`), `markdown` (`.md`), `adoc` (`.adoc`). По умолчанию `markdown` |
| `--output-path`, `-o` | Новый файл отчёта с расширением выбранного формата. Если не указан, используется stdout |
| `--from`, `--to` | Начальная и конечная даты основного периода |
| `--compare-from`, `--compare-to` | Начальная и конечная даты периода сравнения |
| `--help`, `-h` | Справка |
| `--version`, `-V` | Версия программы |

Даты задаются в формате `YYYY-MM-DD`. Границы включительны. Календарная дата
записи определяется в часовом смещении из лога. В обычном режиме любую
границу можно опустить. Если заданы обе, начало должно быть раньше конца.

Для сравнения нужны все четыре даты. Источники читаются один раз,
а каждый период фильтруется независимо. При пересечении периодов
запись учитывается в обоих.

```powershell
.\gradlew.bat -q run --args="--path='samples/logs/access-*.log' --from=2025-03-02 --to=2025-03-03 --compare-from=2025-02-28 --compare-to=2025-03-01"
```

Ожидается по 1500 запросов за каждый период и изменение числа запросов
`0 (0.00%)`. Разница рассчитывается как основной период минус период сравнения,
процент относительно периода сравнения. При нулевой базовой метрике
процент не определён: в JSON выводится `null`, в Markdown и AsciiDoc - `н/д`.

## Отчёты и примеры

Без `--output-path` отчёт выводится в `stdout`. При указании пути он сохраняется
в UTF-8-файл, а `stdout` остаётся пустым. По умолчанию используется Markdown.
Существующий файл не перезаписывается. Родительский каталог должен существовать.

JSON содержит `files`, `totalRequestsCount`, `responseSizeInBytes`
(`average`, `max`, `p95`), `resources`, `responseCodes`, а также данные бонусов.
Markdown и AsciiDoc представляют эти данные таблицами с заголовками.

Примеры для локальной демонстрации сохраняются в `build/report-samples`:

```powershell
New-Item -ItemType Directory -Force -Path build/report-samples | Out-Null

.\gradlew.bat -q run --args="--path='samples/logs/access-*.log' --output-format=json --output-path=build/report-samples/report-json.json"
.\gradlew.bat -q run --args="--path='samples/logs/access-*.log' --output-format=markdown --output-path=build/report-samples/report-md.md"
.\gradlew.bat -q run --args="--path='samples/logs/access-*.log' --output-format=adoc --output-path=build/report-samples/report-adoc.adoc"
```

В Linux / macOS каталог создаётся командой `mkdir -p build/report-samples`,
а для запуска используется `./gradlew`.

Каталог `build/` исключён из Git.

## Расчёт p95

Используется метод nearest rank. Для `n` ответов берётся размер на позиции
`ceil(0.95 * n)` в ряду размеров по возрастанию. Позиции нумеруются с единицы.
Среднее значение размера и процентные изменения округляются до двух знаков после запятой по правилу `HALF_UP`.

Для двух файлов `access-*.log` без фильтрации p95 равен 5450 байтам.

## Правила чтения источников

### Локальные файлы и glob

Поддерживаются расширения `.log` и `.txt`. Локальный источник должен
существовать и быть обычным файлом. Чтение выполняется построчно в UTF-8.

Glob-маски раскрываются приложением. Из найденных путей выбираются обычные
файлы поддерживаемых расширений. Источники сортируются по строковому
представлению пути, чтобы порядок чтения был стабильным.

Примеры масок:

- `samples/logs/access-*.log` - файлы одного каталога;
- `samples/logs/**/*.log` - файлы во вложенных каталогах;
- `samples/logs/{*.log,**/*.log}` - файлы текущего каталога и вложенных каталогов.

В стандартном Java glob маска `**/*.log` не включает файлы непосредственно
в корневом каталоге поиска. Если подходящих файлов нет, программа завершается
с кодом `2`. Символьные ссылки на каталоги при обходе не раскрываются.

### HTTP и HTTPS

URL должен указывать на путь с расширением `.log` или `.txt`.
Query-параметры не участвуют в проверке расширения. Успешными считаются
HTTP-ответы `2xx`, остальные статусы, включая `404`, приводят к ошибке источника.

HTTP-данные читаются построчно. Кодировка определяется заголовком `Content-Type`,
при её отсутствии или неподдерживаемом значении используется UTF-8.
Таймаут подключения: 10 секунд, таймаут запроса: 30 секунд.
При потоковом чтении таймаут запроса не ограничивает полную длительность
загрузки тела ответа.

### Результат чтения

Сводка показывает источники, число прочитанных и некорректных строк,
а также число запросов за основной период.
Некорректные строки пропускаются с предупреждением `skipped malformed log line`.
При построчном чтении в памяти накапливаются счётчики, в том числе по ресурсам и размерам ответов.

Ошибка любого источника прерывает анализ. Отчёт формируется после успешного
чтения всех источников. Файловые и сетевые ресурсы закрываются после использования.

## Вывод и коды завершения

Сводка чтения и предупреждения выводятся в `stderr`.
Справка и версия выводятся в `stdout`.

| Код | Значение |
|---|---|
| `0` | Успешное выполнение, показ справки или версии |
| `1` | Непредвиденная ошибка |
| `2` | Ошибка аргументов, источника данных или записи отчёта |

## Устройство проекта

| Компонент | Ответственность |
|---|---|
| `Main` | Связывает чтение, анализ, формирование и запись отчёта |
| `IncidentRadarCommand` | Разбор аргументов, преобразование значений и обработка ошибок |
| `AnalysisOptions`, `DateRange`, `OutputFormat` | Настройки запуска и их инварианты |
| `LogSourceResolver` | Выбор локального, glob- или HTTP-источника |
| `LogSource` | Общий контракт построчного чтения |
| `LocalLogSource`, `HttpLogSource` | Чтение источников и управление ресурсами |
| `LogReader`, `LogReadResult` | Передача строк обработчику и сведения о завершённом чтении |
| `LogAnalysisService`, `NginxLogParser`, `DateFilter` | Потоковый анализ, разбор строк и фильтрация по датам |
| `StatisticsAccumulator`, `PeriodComparison` | Расчёт статистики и изменений между периодами |
| `ReportData`, `ReportRenderer` | Данные отчёта и общий контракт форматтеров |
| `JsonReportRenderer`, `MarkdownReportRenderer`, `AsciiDocReportRenderer` | Формирование отчётов в поддерживаемых форматах |
| `ReportWriter` | Вывод в stdout или новый UTF-8-файл с защитой от перезаписи |
