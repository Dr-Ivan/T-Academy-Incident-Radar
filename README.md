# Проект 3. Incident Radar

CLI-утилита для анализа NGINX-логов. Читает логи (файлы, glob-маски или URL),
разбирает строки, фильтрует по датам и собирает статистику.

## Состояние проекта в MR2

Программа читает логи построчно, разбирает записи и фильтрует их по датам.
Она считает количество запросов, распределение кодов ответа, топ-10 ресурсов,
средний и максимальный размер ответа и p95.

**Бонусы MR2**

- **Распределение по дням недели.** Запросы выбранного периода группируются по дням недели. В статистике присутствуют все семь дней, включая дни без запросов.
- **Уникальные протоколы.** Из отобранных записей собирается список протоколов без повторов, например `HTTP/1.1` и `HTTP/2.0`.
- **Сравнение двух периодов.** Один набор логов читается за один проход. Для числа запросов, среднего и максимального размера ответа и p95 рассчитываются разница и процентное изменение относительно периода сравнения.

Формирование и сохранение отчётов относятся к MR3.

## Быстрый старт

Нужен **JDK 25 или новее**. Переменная `JAVA_HOME` должна указывать на JDK.
Gradle устанавливать отдельно не требуется: проект содержит Gradle Wrapper.

Все команды выполняются из корня проекта.

### Windows PowerShell

Один файл:

```powershell
.\gradlew.bat run --args="--path=samples/logs/access-2025-03-01.log"
```

Несколько файлов по маске:

```powershell
.\gradlew.bat run --args="--path='samples/logs/access-*.log'"
```

Справка:

```powershell
.\gradlew.bat run --args="--help"
```

Для одного файла `access-2025-03-01.log` ожидается 1500 строк.
Для маски `access-*.log` ожидается два источника и 3000 строк.

### Linux / macOS

```bash
./gradlew run --args="--path='samples/logs/access-*.log'"
./gradlew run --args="--help"
```

### Особенность glob-масок в Windows

CLI поддерживает обе формы: `--path VALUE` и `--path=VALUE`.

В Windows Java Launcher может раскрыть glob-маску ещё до передачи аргументов
в `main`. Поэтому для запуска через Gradle рекомендуется форма
`--path='samples/logs/access-*.log'`, показанная выше. Тогда маску раскрывает само приложение.

Альтернативно в Windows можно использовать:

```powershell
.\gradlew.bat --% run --args="--path '\"./samples/logs/access-*.log\"'"
```


## Параметры CLI

| Параметр | Назначение |
|---|---|
| `--path`, `-p` | Обязательный источник — локальный файл, glob-маска или HTTP/HTTPS URL |
| `--output-format`, `-f` | Формат отчёта — `json` (`.json`), `markdown` (`.md`), `adoc` (`.adoc`). По умолчанию `markdown` |
| `--output-path`, `-o` | Путь к файлу отчёта с расширением для выбранного формата |
| `--from`, `--to` | Начальная и конечная даты основного периода |
| `--compare-from`, `--compare-to` | Начальная и конечная даты периода сравнения |
| `--help`, `-h` | Справка |
| `--version`, `-V` | Версия программы |

Даты задаются в формате `YYYY-MM-DD`. Границы включительны. Календарная дата
записи определяется в часовом смещении из лога. В обычном режиме любую
границу можно опустить. Если заданы обе, начало должно быть раньше конца.

Для сравнения нужны все четыре даты. Источники читаются один раз,
а каждый период фильтруется независимо. При пересечении периодов
запись учитывается в обоих.

```powershell
.\gradlew.bat run --args="--path='samples/logs/access-*.log' --from=2025-03-02 --to=2025-03-03 --compare-from=2025-02-28 --compare-to=2025-03-01"
```

В сводке ожидается 3000 прочитанных строк, по 1500 запросов за каждый период
и изменение числа запросов `0 (0.00%)`.

## Расчёт p95

Используется метод nearest rank. Для `n` ответов берётся размер на позиции
`ceil(0.95 * n)` в ряду размеров по возрастанию. Позиции нумеруются с единицы.

**Пример.** Для двух файлов `access-*.log` без фильтрации p95 равен 5450 байтам.


## Правила чтения источников

### Локальные файлы и glob

Поддерживаются файлы с расширениями `.log` и `.txt`.

Локальный источник должен существовать и быть обычным файлом.
Чтение выполняется построчно в UTF-8.

Glob-маски раскрываются приложением. Из найденных путей выбираются обычные
файлы поддерживаемых расширений. Источники сортируются по строковому
представлению пути, чтобы порядок чтения был стабильным.

Примеры масок:

- `samples/logs/access-*.log` - файлы одного каталога;
- `samples/logs/**/*.log` - файлы во вложенных каталогах;
- `samples/logs/{*.log,**/*.log}` - файлы текущего каталога и вложенных каталогов.

В стандартном Java glob маска `**/*.log` сама по себе не включает файлы
непосредственно в корневом каталоге поиска.

Если подходящих файлов нет, программа завершается с кодом `2`.
Переход по символьным ссылкам на каталоги при обходе не выполняется.

### HTTP и HTTPS

URL должен указывать на путь с расширением `.log` или `.txt`.
Query-параметры не участвуют в проверке расширения.

Успешными считаются HTTP-ответы `2xx`. Остальные статусы, включая `404`,
приводят к ошибке источника.

HTTP-данные читаются построчно через `BodyHandlers.ofLines()`.
Кодировка определяется заголовком `Content-Type`; при её отсутствии
или неподдерживаемом значении используется UTF-8.

Таймаут подключения: 10 секунд, таймаут запроса: 30 секунд.
При потоковом чтении таймаут запроса не ограничивает полную длительность
загрузки тела ответа.

### Результат чтения

Сводка показывает источники, число прочитанных и некорректных строк,
а также число запросов за основной период.
Некорректные строки пропускаются с предупреждением `skipped malformed log line`.
При построчном чтении в памяти накапливаются счётчики, в том числе по ресурсам и размерам ответов.

Ошибка любого источника прерывает чтение; успешный итоговый
`LogReadResult` в этом случае не возвращается. Файловые и сетевые ресурсы
закрываются через `try-with-resources`.


## Вывод и коды завершения

Сводка, статистика основного периода и предупреждения выводятся в `stderr`.
Справка и версия выводятся в `stdout`.

| Код | Значение |
|---|---|
| `0` | Успешное выполнение, показ справки или версии |
| `1` | Непредвиденная ошибка |
| `2` | Ошибка аргументов или источника данных |


## Устройство проекта

| Компонент | Ответственность |
|---|---|
| `Main` | Создание CLI, запуск чтения и вывод сведений о результате |
| `IncidentRadarCommand` | Разбор аргументов, преобразование значений и обработка ошибок |
| `AnalysisOptions`, `DateRange`, `OutputFormat` | Настройки запуска и их инварианты |
| `LogSourceResolver` | Выбор локального, glob- или HTTP-источника |
| `LogSource` | Общий контракт построчного чтения |
| `LocalLogSource`, `HttpLogSource` | Чтение конкретного типа источника и управление ресурсами |
| `LogReader` | Последовательная передача строк обработчику и подсчёт прочитанного |
| `LogReadResult` | Сведения о завершённом чтении для последующих этапов анализа |
| `LogAnalysisService`, `NginxLogParser`, `DateFilter` | Потоковый анализ, разбор строк и фильтрация записей по датам |
| `StatisticsAccumulator`, `PeriodComparison` | Расчёт статистики и изменений между периодами |
